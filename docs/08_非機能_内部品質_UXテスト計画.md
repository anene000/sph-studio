## 2. 性能・負荷

| ID | 項目 | 手段 | 合格基準 |
|----|------|------|----------|
| P1 | ソルバ スループット | 粒子数を段階的に増やし steps/sec を計測 | 破綻せず線形〜準線形に劣化、粒子数に追随 |
| P2 | API レイテンシ | health/validate/frames のレスポンス時間 | 単発 < 500ms（validate は OBJ 読込含み許容） |
| P3 | 進捗ストリーム | WebSocket の遅延・欠落 | 進捗が連続受信、欠落なしで完了 |
| P4 | 同時実行 | 2 ジョブ連続投入 | 双方 completed、プロセス分離で相互影響なし |
| P5 | 出力サイズ | フレーム/CSV 件数が interval に一致 | 期待フレーム数と一致 |
| P6 | 3D 再生負荷 | 粒子点数に応じた描画（間引き方針） | フリーズせず操作可能（目視） |

## 3. セキュリティ

| ID | 項目 | 手段 | 合格基準 |
|----|------|------|----------|
| S1 | パストラバーサル（モデル配信） | `GET /api/models/../..%2f...` 等 | 404、リポジトリ外を読ませない |
| S2 | 任意ファイル読取 | 存在しない/範囲外パス | 404、例外を漏らさない |
| S3 | サブプロセス注入 | scene 値経由のコマンド注入余地 | 引数はリスト渡し・shell 不使用で不可 |
| S4 | 入力検証 | 不正 scene（型・領域） | 422、スタックトレース非露出 |
| S5 | CORS | localhost 以外の Origin | 許可 Origin 限定（3000/tauri） |
| S6 | バインド範囲 | サーバの待受 | localhost のみ、外部公開なし |
| S7 | リソース枯渇 | 巨大 totalSteps/粒子 | フィット検証・voxel0 検出で早期停止（DoS 緩和） |
| S8 | 情報漏洩 | エラーメッセージ | 内部パス最小限、機微情報なし |

## 4. UX

| ID | 項目 | 手段 | 合格基準 |
|----|------|------|----------|
| U1 | ナビゲーション一貫性 | S0〜S7 のステップ移動 | 迷わず往復でき、現在地が分かる |
| U2 | エラー可視化 | バックエンド未接続/検証失敗/インポート失敗 | 画面上に明確なメッセージ |
| U3 | 実行フィードバック | 進捗バー・ETA・ライブログ | 実行中/完了/失敗が判別可能 |
| U4 | 3D 操作性 | OrbitControls・即時反映 | 追加/編集がプレビューに即反映 |
| U5 | レスポンシブ | 幅を変えて破綻がないか | 横スクロール破綻なし（主要幅） |
| U6 | アクセシビリティ | ラベル・フォーカス・コントラスト | 主要操作にラベル、キーボード到達可 |
| U7 | 破壊的操作 | 削除・実行 | 誤操作耐性（ジョブ分離・元設定保持） |

## 5. 実施方法・記録

- 実施環境: Windows 11 / venv(.venv, `SPH_ARCH=cpu`) / Node 24 / pnpm 11。
- 記録先: `docs/09_テスト結果報告.md`（各 ID の実測値・合否）。
- 合否判定: すべての P0 相当（Q1–Q5, S1–S6, U1–U4）が合格で「総合合格」。
  P1 系（性能上限・3D 上限）は測定値を記録し、明確な破綻がなければ合格。
- 不合格が出た場合は修正 → 再実施し、報告に反映してから U17 へ。
