## 1. 改修要件と実装状況（トレーサビリティ）

| # | 改修要件 | 実装 | 検証 |
|---|---------|------|------|
| 1 | 境界の一部を開放境界に指定できる | `periodicBoundary`（軸ごと）で壁を開放。GUI＋scene.json | ✅ 単体・E2E |
| 2 | 周期境界 ON/OFF を GUI/設定で切替 | GUI チェックボックス（X/Y/Z）→ scene.json `periodicBoundary` | ✅ UI・schema |
| 3-a | 周期ON/完全発達流：流入口=流出口で同一プロファイル共有・連続維持（粒子サイズ不変） | 周期循環（位置ラップ＋minimum-image 近傍）＋駆動力 `drivingForce`。粒子数固定 | ✅ 再循環検証 |
| 3-b | 未満水/周期OFF：流速を固定値に固定せず動的制御・流入プロファイル指定 | `inletControl`（流入ゾーンで目標速度へ緩和、uniform/parabolic、`inletRelaxation`） | ✅ 流入検証 |

**受入条件の充足**

- 「境界の開放位置」「周期計算 ON/OFF」「流入口/流出口の流速プロファイル」をパラメータで設定・切替可能 → **達成**（GUI/JSON 両対応、schema 検証あり）。
- 未満水でも指定境界条件に従い滑らかに流入・追従、非不連続な流れ場 → **達成**（`sample_inlet_channel` で流入ゾーンが目標へ追従、有限・連続）。
- 周期ON で流出粒子が流入口へ循環し破綻なく連続実行 → **達成**（seam を 70 回横断しても有限・領域内）。

## 2. 機能テスト（Functional）

### 2.1 バックエンド／スキーマ（pytest）

`SPH_ARCH=cpu pytest backend -q` → **24 passed**。

- `test_schema.py`: 周期境界・駆動力・流入制御の各キーについて、既定値（OFF/0）・エクスポート往復・次元不一致/範囲外の検証エラーを確認。
- `test_samples.py`: 全 `sample_*.json`（`sample_periodic_channel`, `sample_inlet_channel` を含む）がスキーマ検証・フィット検証を通過。
- `test_e2e.py`: 実ソルバ（WCSPH）をサブプロセス起動し CSV 生成までを確認（CPU）。

### 2.2 ソルバ ヘッドレス検証（CPU）

| シーン | 手法 | 結果 |
|--------|------|------|
| `sample_periodic_channel`（x周期＋駆動力） | WCSPH | done・error 記録なし・CSV 全値有限 |
| 同上 | DFSPH | done・error 記録なし・CSV 全値有限（**method 4 復活**） |
| 周期＋初速プラグ流（再循環） | WCSPH | seam 横断 **70 回**・NaN/領域外なし |
| `sample_inlet_channel`（未満水・放物線流入） | WCSPH | 流入ゾーン平均 vx が目標へ追従・有限・連続 |

> DFSPH は改修前、共有近傍探索のスカラー添字化に未追従（`ti.grouped` による添字不一致）で **コンパイル不能** だった。本改修で `range(particle_num)` へ統一し `simulationMethod=4` が復活。

### 2.3 GUI（S2 パラメータ画面）

- 「境界条件（開放・周期境界）」セクション：周期 X/Y/Z トグル、駆動力 (x,y,z)、流入速度制御を追加。
- `inletControl` ON で流入軸/流入側/流入速度/厚み/緩和/プロファイル（uniform・parabolic＋横断軸）が条件表示されることをブラウザで確認（要素・条件レンダリング・値反映）。

## 5. パフォーマンステスト

計測環境: Windows 11 / CPU（`SPH_ARCH=cpu`, Taichi 1.7.4）/ WCSPH。

### 5.1 機能オーバーヘッド（純ソルバ throughput, 875 粒子, warmup 除外）

| 条件 | steps/sec | 相対 |
|------|-----------|------|
| 壁境界（周期OFF）＋駆動力 | 390.0 | 1.00 |
| 周期境界 x ＋駆動力 | 438.8 | 1.12 |
| 周期境界 x ＋流入速度制御 | 417.1 | 1.07 |

- 周期境界の追加オーバーヘッド: **約 −11%（＝むしろ高速）**。周期軸はセルをラップするだけで、壁の衝突応答（per-particle collision）より軽いため。
- 流入速度制御の追加オーバーヘッド: **約 +5%**（毎ステップ 1 カーネルの追加）。
- いずれも実用上無視できる範囲で、既存性能を損なわない。

### 5.2 サブプロセス端点 throughput（`benchmark.py` P1, JIT 起動込み）

| 粒子半径 | 粒子数 | steps/sec |
|----------|--------|-----------|
| 0.03 | 810 | 17.5 |
| 0.02 | 2535 | 16.4 |
| 0.015 | 5780 | 15.1 |

（`run_headless` をジョブ毎に起動する経路。Taichi 初期化/JIT を含むため §5.1 の純ソルバ値より低い。粒子数増加に対し概ね線形で劣化。）

### 5.3 API レイテンシ / 同時実行（P2, P4/P5）

- `GET /api/health` 18.4 ms、`POST /api/config/validate` 81.7 ms。
- 2 ジョブ同時実行が両方 `completed`（フレーム出力あり）。

観察:

- 本改修の追加コストはソルバ 1 ステップあたり僅少で、周期化はむしろ壁処理より軽い。
- 流入制御・周期境界とも粒子数固定のため、メモリ/確保挙動は既存と同等。
