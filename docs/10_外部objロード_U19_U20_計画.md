- 作成日: 2026-07-30

## A. 外部 .obj メッシュの読み込み

### 現状と課題
- `RigidBodies[].geometryFile` は `data/models` 相対（またはソルバは任意パスを `trimesh.load`）。
- GUI（S1）は `data/models` 内の一覧からしか選べず、リポジトリ外の .obj を取り込めない。
- ブラウザはローカル任意パスを直接読めないため、外部ファイルは「アップロード」か
  「サーバ側の追加ディレクトリ参照」で取り込む必要がある。

### 方針（2 経路）
1. **アップロード（主経路・全環境で動作）**: S1 に「外部 .obj を取り込む」ボタンを追加。
   OS のファイルピッカーで任意の .obj を選択 → `POST /api/models`（既存）で `data/models` に
   登録 → 一覧に反映 → 剛体として追加。
2. **外部ディレクトリ参照（サーバ設定）**: 環境変数 `SPH_EXTRA_MODELS_DIR`（`os.pathsep` 区切りで
   複数可）を追加。`GET /api/models` は data/models と各外部ディレクトリを集約（`dir:name` 形式で
   出所も返す）。`GET /api/models/{name}` は全ディレクトリを探索（各ディレクトリ配下に限定＝
   パストラバーサル防止）。`geometryFile` の絶対パスもソルバ/検証で解決可能（既存挙動を明文化）。

### 受入基準 / テスト
- `SPH_EXTRA_MODELS_DIR` の .obj が一覧・配信・プレビューできる。
- アップロードした .obj が登録され利用できる。
- パストラバーサル（`..`）は各ルート外を返さない（404）。
- 既存サンプル・E2E が緑のまま。CI（Taichi 無し）でも新テストが通る。

## B. U19: Python(FastAPI) サイドカー同梱

- **統一エントリポイント**: backend を PyInstaller で 1 バイナリ化（`sph-backend`）。ソルバは
  従来 `python run_headless.py` を別プロセス起動していたが、frozen 環境では `sys.executable` が
  exe になるため、**自己再呼び出し方式**（`sph-backend --run-solver --scene_file ... --output_dir ...`）
  へ変更。`jobs.py` は frozen 判定（`sys.frozen`）でコマンドを切替。
- **PyInstaller spec**: backend + solver + taichi/trimesh のデータ/隠しimportを収集。
- **Tauri 連携**: `tauri-plugin-shell` を追加、`bundle.externalBin=["binaries/sph-backend"]`、
  `capabilities` に `shell:allow-execute`/sidecar 権限、`lib.rs` の `setup` で起動・終了管理。
- **ビルド補助**: `scripts/build_sidecar.(sh|ps1)`。
- 検証: サイドカーのディスパッチ論理（python 実行）＋ Tauri（shell plugin 込み）の Rust ビルド。
  frozen バイナリの Taichi 同梱は環境依存が大きいため spec とビルド手順を用意し、可能な範囲で確認。

## C. U20: OS 別ビルド / Release CI

- 既存 `ci.yml`（lint/test/build）は**据え置き**（push/PR で緑を維持）。
- 新規 `release.yml` を**タグ（`v*`）トリガ**で追加: ubuntu/windows/macos マトリクスで
  PyInstaller サイドカー→`tauri build`→インストーラを Release へアップロード。
- 常時 push では走らせない（CI 分数・失敗ノイズ回避）。タグ時のみ実行し成果物添付。

## 実施順
1. A（外部obj）: 実装→テスト→コミット→push→CI緑確認。
2. B（U19）: 実装→ビルド確認→コミット→push。
3. C（U20）: `release.yml` 追加→コミット→push→`ci.yml` 緑維持確認。
